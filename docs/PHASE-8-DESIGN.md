## مبادئ التنفيذ

يظل التنفيذ داخل GitHub Actions وGitHub Pages، ولا يضيف خادمًا أو موقعًا مستقلًا أو خدمة مدفوعة. مدخلات الجمهور ومخرجات LLM بيانات غير موثوقة، ولا تُنفّذ أو تُضمّن مباشرة في كود أو أوامر shell. لا يُحذف أي منتج منشور، ولا يُعاد استخدام مساره، ولا يُعدل backlog النهائي تلقائيًا من مرحلة 7.

يبدأ الإصلاح بالتدريج: تقوية بوابات الأمان وoutputs، ثم lifecycle للتقاعد وإعادة البناء، ثم تحسين القفل والاعتمادية. لا يُفعّل matrix أو التشغيل المتوازي للكتابة إلى `main` في هذه المرحلة؛ لا يُبرر ذلك حجم backlog الحالي.

## نطاق العمل

### أ. تقوية الأمن

إنشاء فاحص مركزي أو توسيع الاختبارات الحالية للتحقق من الروابط الخارجية، scripts وstylesheets وiframes وforms وnetwork APIs وcredential-like literals وخصائص المتصفح الحساسة. يجب أن تظل CounterAPI الاستثناء الخارجي الوحيد المسموح به بعد الحقن النهائي.

إضافة regression fixtures لمنتج صالح، منتج يحاول `fetch` أو `WebSocket` أو `iframe` أو `javascript:`، ومنتج يحاول رابطًا خارجيًا أو literal يشبه سرًا. يجب أن تفشل البوابة قبل النشر، وأن تجتاز النسخة الصحيحة فقط.

### ب. دورة حياة المنتج

إضافة metadata اختيارية مثل `lifecycle`, `retirement_reason`, `retired_at`, `revisit_at`, و`replacement_url`، مع قيم مقيدة. تعديل picker ليمنع `retired` و`revisit` من الاختيار العادي. تعديل catalog ليعرض حالة المنتج المتقاعد أو رابط البديل دون حذف الصفحة القديمة.

إنشاء مسار يدوي واضح لتقاعد فكرة أو وضعها في `revisit`. هذا المسار لا يعمل على المنتج المنشور نفسه، ولا يزيله من GitHub Pages، ولا يكتب إلا بعد تأكيد رقم الفكرة أو slug وفحوص schema.

### ج. الاعتمادية

توحيد قفل الكتابة لمساري Tier A وLLM، وإضافة فحص stale main قبل push أو مسار فشل آمن عند تعارضه. إبقاء `cancel-in-progress=false` حتى لا يُقتل تشغيل كاتب في منتصف النشر. إزالة outputs غير الضرورية، خصوصًا model، وتقليل البيانات المرسلة إلى Telegram.

### د. التقاعد وإعادة البناء

أي إعادة بناء تنتج period أو slug جديدًا، وتبقى النسخة الأصلية قابلة للوصول. لا يوجد `--overwrite` في التشغيل الآلي. المنتج المتقاعد يظل في catalog مع شارة الحالة، بينما يمنع picker اختياره مرة أخرى.

## بوابات المرحلة

لا تنتقل المرحلة إلى الاختبار الحقيقي إلا بعد نجاح Python/YAML/JSON وfixtures الأمنية، واختبار lifecycle محلي، والتحقق من أن picker لا يختار المتقاعد، وأن catalog يحافظ على الروابط القديمة، وأن workflow لا يكتب output حساسًا.

لا تُغلق المرحلة إلا بعد تشغيل GitHub حقيقي لمسار Tier A أو workflow lifecycle، واختبار فشل أمني، واختبار تشغيلين متزامنين أو محاكاة stale main، والتحقق من Pages وTelegram، ثم توثيق النتائج وتنظيف الفرع. لا تبدأ مرحلة 9.
